# QA 체크리스트 (report-qa용)

## 1. 커버리지

- [ ] brief의 영상 전부가 리포트에 등장하는가 (누락 영상은 '소스 및 누락'에 명시됐는가)
- [ ] 각 영상 분석의 claims 중 리서치 질문 관련 주요 주장이 누락 없이 반영됐는가 (전량이 아니라 주요 주장 기준)
- [ ] 사이트 nav_map의 모든 섹션이 개요·심층 어딘가에 반영됐거나 미반영 사유가 있는가
- [ ] 리서치 질문 각각에 명시적 답변이 존재하는가 (Executive Summary 포함)

## 2. 독자 가독성 (내부 코드 노출 — blocker)

- [ ] 본문(문단·소제목·이미지 캡션)에 `[V1 7:39]`, `[Docs:tasks]` 형태의 내부 태그가 없는가
- [ ] "V1은 ~했다" 식의 코드 주어가 없는가 — 소스가 채널명·자연어로 지칭되는가
- [ ] confirm / conflict / unverified 영문 라벨이 본문에 그대로 쓰이지 않았는가 (✅ 확인 / ⚠️ 상충 / ❓ 미확인 표기여야)
- [ ] "병기" 등 하네스 내부 용어가 독자 용어로 풀어졌는가
- [ ] 축약 코드를 쓴 표 바로 위에 출처 범례가 있는가
- [ ] 소스 표에 별칭 컬럼이 있고, 본문의 짧은 지칭과 일치하는가

## 3. 출처 무결성 (hallucination 방어)

- [ ] 각주 5개 이상 랜덤 추출 → 원본 JSON 레코드·타임스탬프와 대조 → 일치? (spot_checks에 기록)
- [ ] 각주 딥링크 URL이 실제 소스 URL과 일치하는가
- [ ] 자연어 지침 문장("○○ 리뷰는 ~라고 한다") 5개 이상 추출 → 실제 해당 소스의 주장인가
- [ ] 출처를 특정할 수 없는 평가문이 있는가 (있으면 blocker)

## 4. 타임스탬프·URL

- [ ] 모든 각주·캡션·표의 타임스탬프(분:초 → 초 환산)가 해당 영상 duration 이내인가
- [ ] 부록 딥링크의 URL·초가 실제 소스와 일치하는가

## 5. 상충·투명성

- [ ] 소스 간 상충이 양쪽 표기되었는가 (한쪽만 실린 상충 후보를 찾아 확인)
- [ ] 상충이 임의로 확인(✅)으로 둔갑하지 않았는가
- [ ] 누락 소스·실패 페이지(pages_failed)가 리포트에 명시되었는가

## 6. 구조·문체

- [ ] 목차가 소스 나열이 아니라 리서치 질문을 따르는가
- [ ] 리뷰별 리캡 나열 구간이 있는가 (있으면 minor)
- [ ] 눈높이가 brief의 audience와 일치하는가

## verdict 규칙

- 1~5번 영역의 위반 = **blocker** → `fail`
- 6번 영역 위반 = **minor** → `pass_with_fixes`
- `spot_checks`에 대조 결과 최소 5건 기록 (각주·자연어 지칭 혼합)
