# Tab 악보 추출 가이드

기타 연습 영상에서 스크롤되는 tab 악보를 시각적으로 분석하여 완전한 텍스트 tab으로 변환하는 방법론.

## Tab 악보 인식

### 표준 Tab 형식

기타 tab은 6개 줄로 표현되며, 각 줄은 기타의 현을 나타낸다:

```
e|---0---1---3---5---|   ← 1번현 (가장 높은 음)
B|--1---1---0---0----|   ← 2번현
G|-2---2---0---0-----|   ← 3번현
D|-------------------|   ← 4번현
A|-------------------|   ← 5번현
E|-------------------|   ← 6번현 (가장 낮은 음)
```

### 영상에서의 Tab 형태

1. **ASCII Tab** — 6줄의 텍스트 형태. 숫자가 프렛 위치
2. **Guitar Pro / TuxGuitar 스타일** — 5선지 위에 숫자가 표시
3. **색상 코딩** — 현재 연주 중인 음이 하이라이트됨
4. **리듬 표기** — 음표 길이가 표시된 고급 tab

## 프레임 분석 전략

### 중첩(Overlap) 감지

연속된 프레임 간에 tab이 스크롤되므로 중첩 구간이 존재한다:

1. 프레임 N과 N+1을 비교
2. 프레임 N의 **오른쪽 끝 부분**이 프레임 N+1의 **왼쪽 시작 부분**과 일치하는지 확인
3. 일치하는 구간은 중복이므로 한 번만 기록
4. 프레임 N+1에서 **새로 나타난 내용만** 추가

### 스크롤 패턴

| 패턴 | 설명 | 대응 |
| --- | --- | --- |
| **부드러운 스크롤** | 일정한 속도로 오른쪽으로 이동 | 중간 프레임 건너뛰고 겹침 부분만 확인 |
| **멈춤 + 점프** | 잠시 멈춤 후 새 구간으로 점프 | 점프 지점에서 완전히 새로운 내용 시작 |
| **역방향** | 드물지만 왼쪽으로 스크롤 | 프레임 순서 확인, 역방향이면 재배열 |
| **반복** | 같은 구간이 다시 나옴 (리프 반복 등) | 동일 내용은 한 번만 기록, 반복 표시 추가 |

## 텍스트 Tab 생성 규칙

### 기본 형식

```
[Intro]  0:00 - 0:15
e|-----------------|-----------------|
B|-----------------|-----------------|
G|-------0---------|-------2---------|
D|-----2-------2---|-----0-------0---|
A|---3-------3-----|---2-------2-----|
E|-----------------|-----------------|

[Verse]  0:16 - 0:45
e|-----------------|-----------------|
B|-------1---------|-------3---------|
G|-----0-------0---|-----0-------0---|
D|-----------------|-----------------|
A|-3-------3-------|-2-------2-------|
E|-----------------|-----------------|
```

### 섹션 구분

- 영상에서 **섹션 전환**이 보이면 새로운 헤더 추가 (Intro, Verse, Chorus, Bridge, Solo 등)
- 섹션 헤더에 **시간대** 표기
- 반복되는 섹션은 `(x2)`, `(x4)` 등으로 횟수 표시

### 특수 기호

| 기호 | 의미 |
| --- | --- |
| `h` | 해머온 (hammer-on) |
| `p` | 풀오프 (pull-off) |
| `/` | 슬라이드 업 |
| `\` | 슬라이드 다운 |
| `b` | 벤딩 (bend) |
| `r` | 벤드 후 릴리즈 |
| `~` | 비브라토 |
| `x` | 뮤트 |
| `t` | 태핑 |
| `pm` | 팜 뮤트 |
| `harm` | 하모닉스 |

## 품질 기준

### 필수 확인 사항

1. **6줄 완전성** — 모든 현(E, A, D, G, B, e)이 누락 없이 표시
2. **프렛 정확도** — 숫자가 올바른 프렛 위치인지 교차 검증
3. **시간 순서** — 프레임 타임스탬프 순서대로 배열
4. **중복 제거** — 동일 구간이 여러 프레임에 걸쳐 나타나면 한 번만 기록
5. **간격 일관성** — 마디 간격(`|`)이 규칙적으로 유지

### 불확실한 부분 처리

- 프레임이 흐리거나 가려서 읽기 어려운 부분은 `?`로 표시
- 추정값은 `(~)`로 감싸서 표시: 예 `e|---(~3)---|`
- 여러 가능성이 있으면 모두 기록: `e|---3/5---|` (3 또는 5)

## 에러 복구

| 문제 | 대응 |
| --- | --- |
| 프레임 수가 너무 적음 (&lt; 5개) | FPS를 높여 재추출 권장 (`--fps 5`) |
| 프레임이 너무 많음 (&gt; 500개) | 임계값 낮춰 재추출 권장 (`--threshold 4`) |
| Tab 영역이 화면에 안 보임 | 해당 프레임은 건너뛰고 다음 프레임 분석 |
| 읽을 수 없는 해상도 | `--max-width 1920`으로 재추출 권장 |
